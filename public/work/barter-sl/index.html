The experiment

Barter-SL explores a mobile marketplace idea through Android screens, sample data and locally persisted application state.

It is a prototype for learning and evaluating flows, rather than a launched marketplace.

My role

I used AI development tools to help implement and inspect the Android project, explore its structure and work through interface and data-flow ideas.

Kotlin and Room belong in my “implemented with AI assistance” experience. This project does not establish independent mastery of Android engineering.

What exists

  • Android application structure and UI flows.
  • Repository and view-model code.
  • A local Room database.
  • Sample listings and simulated peer replies.

The boundary

There is no claim here of a production marketplace, live multi-user messaging, real transactions or a deployed backend. The diagram is a project overview, not a screenshot of a released application.

What comes next

Better tests, clearer data boundaries and more practice explaining the code independently. A real multi-user version would require backend design, authentication, authorization and end-to-end verification.
